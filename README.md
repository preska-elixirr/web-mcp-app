# Office Supply — WebMCP demo

A fictional office webshop built with Next.js App Router, TypeScript, Tailwind CSS, shadcn/ui (Base UI), and Zod. It is the foundation for the WebMCP walkthrough in [PLAN.md](./PLAN.md).

## Current status

The application runs locally with a seeded 16-product catalog, search and filters, product details, stock-validated cart operations, versioned cart persistence, checkout review, a simulated receipt, and demo reset. Native WebMCP tool registration, the tool activity panel, Vercel deployment, and article materials are the next stages.

## Requirements and startup

- Node.js 24 or later (tested with 24.19.0).
- pnpm 11.19.0 (the package manager used to create the lockfile).
- No environment variables, API keys, database, or external product services.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Open http://localhost:3000. For production mode, run `pnpm build` and then `pnpm start`.

## Checks

```sh
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

`pnpm check` runs all four checks. `pnpm format` applies Biome formatting and safe lint fixes. `pnpm test:watch` runs Vitest interactively.

Biome is used for linting and formatting: the current ESLint plugins bundled with `eslint-config-next` declare incompatible peers for ESLint 10 and TypeScript 7. Biome lets this project use the latest stable TypeScript without overriding those compatibility constraints.

## Project structure

```text
app/                   Next.js routes, root layout, metadata, global styles
components/            Storefront, product cards, and cart panel
  ui/                  Official shadcn components generated by its CLI
lib/                   Seed data, Zod schemas, shared domain operations, reducer
tests/                 Domain, persistence, and checkout lifecycle tests
docs/                  Version verification and implementation notes
components.json        shadcn configuration and import aliases
next.config.ts         Next.js configuration
tsconfig.json          Strict TypeScript configuration; @/* points to the root
biome.json             Linting and formatting configuration
package.json           Dependencies and scripts
pnpm-lock.yaml         Reproducible dependency resolutions
```

This is the official root `app/` convention for the App Router; a `src/` directory is optional. shadcn files live in `components/ui/`, not in the project root. The project was installed manually to preserve the existing Git repository, README, and plan; this is supported by the [Next.js installation guide](https://nextjs.org/docs/app/getting-started/installation#manual-installation).

## Shared operations and reproducible scenario

`lib/domain.ts` owns product search, product details, additive cart updates, absolute quantity updates, cart totals, checkout preparation, and persistence validation. Both the manual UI and future WebMCP handlers will use these operations. Prices are stored and calculated in integer EUR cents.

The cheapest in-stock wireless products are:

- 2 × Air Wireless Keyboard (`kb-air`) at €34.90 each.
- 2 × Air Wireless Mouse (`mouse-air`) at €19.90 each.
- Total: **€109.60**, leaving €70.40 of the €180 budget.

Cart mutations invalidate the prepared checkout review. Only the manual confirmation button creates a simulated receipt and clears the cart. Stock is static demo data and is not depleted by simulated orders. The versioned localStorage payload stores product IDs and quantities; prices and stock always come from the seeded catalog. Invalid saved data is discarded safely, and the UI remains usable when browser storage is blocked.

## View transitions

React 19.3's `<ViewTransition>` coordinates the browser's native View Transition API for catalog filtering, sorting, and cart changes. Discrete updates use `startTransition`; search typing stays urgent while the result view uses `useDeferredValue`. Each product and cart line has a uniquely named React boundary.

`lib/view-transitions.ts` checks for `document.startViewTransition` and `prefers-reduced-motion`. Unsupported browsers apply state updates immediately; CSS also disables animations for reduced-motion users. No animation library or React canary dependency is required. The app does not yet contain route navigation that needs cross-document transitions.
